# Rasheed - Finance Savings Agent — مرجع الـ API

الإصدار: `0.1.0`

**رشيد** تطبيق لإدارة المصاريف والتوفير، مبني حول وكيل ذكاء اصطناعي (رشيد) بثلاث شخصيات.
هذا الـ Backend بيخدّم تطبيق الموبايل (Flutter).

## البدء السريع (من هذه الصفحة)

1. نفّذ `POST /auth/register` (أو `POST /auth/login` إذا عندك حساب).
2. انسخ قيمة `access_token` من الرد.
3. اضغط زر **Authorize** أعلى الصفحة وألصق التوكن (بدون كلمة Bearer).
4. جرّب أي Endpoint محمي (القفل 🔒 بجانبه).

## مبادئ عامة

- **المصادقة:** JWT من نوع Bearer عبر الهيدر `Authorization: Bearer <access_token>`.
  كل الـ Endpoints محمية ما عدا `/auth/*` و`/personas` و`/health`.
- **العملة:** كل المبالغ بالدينار الأردني (JOD).
- **المسودات لا تحفظ شيئًا:** `/transactions/scan-receipt` و`/transactions/parse-sms`
  و`/transactions/sms-import/preview` تقرأ وتحلّل فقط. الحفظ الفعلي دايمًا بطلب منفصل
  يقرّره المستخدم بعد مراجعة المسودة.
- **رشيد لا يعدّل بياناتك بدون موافقة:** أي تغيير مالي يقترحه رشيد (تصحيح تصنيف، دفعة لهدف،
  هدف جديد، تسجيل دخل) يُنشأ كاقتراح بحالة `pending`، ولا يُنفَّذ إلا عند
  `POST /agent/actions/{id}/confirm` بطلب صريح من المستخدم.
- **ازدحام Gemini:** عند ازدحام خدمة الذكاء الاصطناعي، `/agent/chat` يرجّع `200` مع رسالة اعتذار
  نصية داخل `reply` بدل خطأ HTTP.

## صيغة الأخطاء

أخطاء المنطق ترجع بالشكل `{"detail": "رسالة بالعربي"}` مع كود HTTP مناسب
(400 طلب غير صالح، 401 غير مصادَق، 404 غير موجود، 409 تعارض).
أخطاء التحقق من المدخلات (Validation) ترجع `422` بالصيغة القياسية لـ FastAPI.

## Auth

إنشاء الحساب وتسجيل الدخول (ترجع توكنات JWT).

| الطريقة | المسار | المصادقة | الملخص |
|---|---|---|---|
| POST | `/api/v1/auth/register` | لا | إنشاء حساب جديد |
| POST | `/api/v1/auth/login` | لا | تسجيل الدخول |

### إنشاء حساب جديد

`POST /api/v1/auth/register`

ينشئ حسابًا جديدًا ويرجّع زوج التوكنات (`access_token` و`refresh_token`) مع بيانات المستخدم. رقم الهاتف فريد، وكلمة المرور 8 أحرف على الأقل.

**المصادقة:** غير مطلوبة

**جسم الطلب** (`application/json`):

| الحقل | النوع | مطلوب | الوصف |
|---|---|---|---|
| `name` | string | نعم | الاسم الظاهر للمستخدم |
| `phone` | string | نعم | رقم الهاتف — فريد لكل حساب |
| `password` | string | نعم | 8 أحرف على الأقل |
| `income_type` | enum: fixed \| variable | لا | `fixed` دخل ثابت (راتب)، أو `variable` دخل غير منتظم (فريلانس/أجرة يومية) |

مثال:

```json
{
  "income_type": "variable",
  "name": "سامر",
  "password": "Passw0rd!",
  "phone": "0791234567"
}
```

**الردود:**

| الكود | الوصف |
|---|---|
| 201 | نجاح العملية. |
| 409 | رقم الهاتف مسجّل مسبقًا. |
| 422 | خطأ تحقق من المدخلات (صيغة FastAPI القياسية). |

### تسجيل الدخول

`POST /api/v1/auth/login`

يتحقق من رقم الهاتف وكلمة المرور ويرجّع زوج التوكنات مع بيانات المستخدم.

**المصادقة:** غير مطلوبة

**جسم الطلب** (`application/json`):

| الحقل | النوع | مطلوب | الوصف |
|---|---|---|---|
| `phone` | string | نعم | رقم الهاتف المسجَّل |
| `password` | string | نعم | كلمة المرور |

مثال:

```json
{
  "password": "Passw0rd!",
  "phone": "0791234567"
}
```

**الردود:**

| الكود | الوصف |
|---|---|
| 200 | نجاح العملية. |
| 401 | رقم الهاتف أو كلمة المرور غير صحيحة. |
| 422 | خطأ تحقق من المدخلات (صيغة FastAPI القياسية). |

## Onboarding

إعداد الحساب لأول مرة: نوع الدخل، شخصية رشيد، وأول هدف.

| الطريقة | المسار | المصادقة | الملخص |
|---|---|---|---|
| POST | `/api/v1/onboarding/complete` | نعم | إتمام الـ Onboarding |

### إتمام الـ Onboarding

`POST /api/v1/onboarding/complete`

يستقبل مخرجات شاشات الإعداد بطلب واحد: نوع الدخل، الشخصية المختارة، وأول هدف مالي. يحفظ الشخصية وينشئ الهدف ويعلّم الحساب بأنه أكمل الإعداد. يُنفَّذ مرة واحدة فقط لكل حساب.

**المصادقة:** مطلوبة (Bearer)

**جسم الطلب** (`application/json`):

| الحقل | النوع | مطلوب | الوصف |
|---|---|---|---|
| `income_type` | enum: fixed \| variable | نعم | `fixed` أو `variable` |
| `persona_id` | string (uuid) | نعم | معرّف الشخصية من `GET /personas` |
| `goal_title` | string | نعم | عنوان أول هدف |
| `goal_target_amount` | number | نعم | المبلغ المستهدف لأول هدف (دينار) |
| `goal_deadline` | string (date) (أو null) | لا | موعد نهائي اختياري |

مثال:

```json
{
  "goal_target_amount": 1000,
  "goal_title": "صندوق الطوارئ",
  "income_type": "variable",
  "persona_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6"
}
```

**الردود:**

| الكود | الوصف |
|---|---|
| 200 | نجاح العملية. |
| 401 | التوكن ناقص أو غير صالح أو منتهي الصلاحية، أو المستخدم غير موجود/غير مفعّل. |
| 400 | المستخدم أكمل الـ Onboarding سابقًا. |
| 404 | الشخصية المختارة غير موجودة. |
| 422 | خطأ تحقق من المدخلات (صيغة FastAPI القياسية). |

مثال على الرد `200`:

```json
{
  "agent_name": "رشيد",
  "has_completed_onboarding": true,
  "id": "9c1d2e4a-7b3f-4d58-a1c6-0e5f8b2d7a91",
  "income_type": "variable",
  "name": "سامر",
  "persona": {
    "color_hex": "#F57C00",
    "display_name": "رشيد الطاقة",
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",

  },
```

## Goals

الأهداف المالية (الخطط). تدعم الأولويات، والأهداف الشهرية المتكررة (مصاريف ثابتة تُصفَّر تلقائيًا كل شهر بعد اكتمالها).

| الطريقة | المسار | المصادقة | الملخص |
|---|---|---|---|
| GET | `/api/v1/goals` | نعم | قائمة الأهداف |
| POST | `/api/v1/goals` | نعم | إنشاء هدف |
| PUT | `/api/v1/goals/reorder` | نعم | إعادة ترتيب الأولويات |
| POST | `/api/v1/goals/{goal_id}/contribute` | نعم | إضافة مبلغ لتقدّم هدف |
| DELETE | `/api/v1/goals/{goal_id}` | نعم | حذف هدف |

### قائمة الأهداف

`GET /api/v1/goals`

يرجّع كل أهداف المستخدم مرتبة حسب الحالة ثم الأولوية. يُطبَّق عند القراءة التصفير الشهري للأهداف المتكررة. `progress_percentage` محسوبة من `current_amount` و`target_amount`.

**المصادقة:** مطلوبة (Bearer)

**الردود:**

| الكود | الوصف |
|---|---|
| 200 | نجاح العملية. |
| 401 | التوكن ناقص أو غير صالح أو منتهي الصلاحية، أو المستخدم غير موجود/غير مفعّل. |

مثال على الرد `200`:

```json
[
  {
    "created_at": "2026-08-08T10:47:45Z",
    "current_amount": 510,
    "deadline": "2027-01-05",
    "icon": "laptop",
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "is_recurring": false,
    "priority": 2,
    "progress_percentage": 85.0,
    "status": "active",
    "target_amount": 600,
    "title": "لابتوب جديد"
  }
]
```

### إنشاء هدف

`POST /api/v1/goals`

ينشئ هدفًا جديدًا بأولوية في آخر الترتيب. إذا كان `is_recurring=true` يصبح «مصروفًا شهريًا ثابتًا»: يُصفَّر تلقائيًا في بداية كل شهر بعد أن يكتمل في الشهر السابق.

**المصادقة:** مطلوبة (Bearer)

**جسم الطلب** (`application/json`):

| الحقل | النوع | مطلوب | الوصف |
|---|---|---|---|
| `title` | string | نعم | عنوان الهدف |
| `icon` | string | لا | مفتاح أيقونة يفسّره تطبيق الموبايل (مثل laptop أو plane) |
| `target_amount` | number | نعم | المبلغ المستهدف بالدينار |
| `deadline` | string (date) (أو null) | لا | الموعد النهائي (اختياري) |
| `is_recurring` | boolean | لا | true = مصروف شهري ثابت يُصفَّر تلقائيًا كل شهر بعد اكتماله |

مثال:

```json
{
  "deadline": "2027-01-05",
  "icon": "laptop",
  "is_recurring": false,
  "target_amount": 600,
  "title": "لابتوب جديد"
}
```

**الردود:**

| الكود | الوصف |
|---|---|
| 201 | نجاح العملية. |
| 401 | التوكن ناقص أو غير صالح أو منتهي الصلاحية، أو المستخدم غير موجود/غير مفعّل. |
| 422 | خطأ تحقق من المدخلات (صيغة FastAPI القياسية). |

مثال على الرد `201`:

```json
{
  "created_at": "2026-08-08T10:47:45Z",
  "current_amount": 510,
```

|---|---|---|---|
| `amount` | number | نعم | المبلغ المضاف بالدينار |

### رفض اقتراح

`POST /api/v1/agent/actions/{action_id}/reject`

يحوّل حالة الاقتراح إلى `rejected` دون أي تعديل على بيانات المستخدم.

**المصادقة:** مطلوبة (Bearer)

**المعاملات:**

| الاسم | المكان | النوع | الوصف |
|---|---|---|---|
| `action_id` | path | string (uuid) |  |

**الردود:**

| الكود | الوصف |
|---|---|
| 200 | نجاح العملية. |
| 401 | التوكن ناقص أو غير صالح أو منتهي الصلاحية، أو المستخدم غير موجود/غير مفعّل. |
| 400 | الاقتراح تم الرد عليه سابقًا. |
| 404 | الاقتراح غير موجود. |
| 422 | خطأ تحقق من المدخلات (صيغة FastAPI القياسية). |
