## 2. كيف تشغّل الاختبارات

```powershell
cd mobile
flutter pub get
flutter test
```

إذا فشل `pub get` بسبب `intl`: تأكد إن `pubspec.yaml` فيه `intl: any` (مش `^0.19.0`).
`flutter_localizations` بيفرض نسخة محددة من `intl` حسب نسخة Flutter عندك.

الاختبارات (`test/accessibility_test.dart`) بتغطي:
- **التباين:** ألوان الشخصيات، النص الثانوي، المبالغ، وكل شارات المعاملة ≥ 4.5:1.
- **RTL وتكبير الخط:** `TransactionTile` بـ 100% و150% و200% ببيانات مختلفة بدون overflow، واتجاه الشاشة rtl واللغة ar.
- **عدم الاعتماد على اللون وحده:** إشارة +/-، مصدر المعاملة بنص، "تصنيف تلقائي X%"، "بدون تصنيف"، ووصف قارئ الشاشة للبطاقات.

**حدود الاختبارات:** بتغطي widgets مستقلة فقط (`TransactionTile` و`SelectableCard`). الشاشات الكاملة (الشاشة الرئيسية، المحادثة،
مسار الهدف...) بتحتاج بيئة Riverpod وAPI وهمي، وما أضفتها. وبالاختبارات الخط الافتراضي (Ahem) أعرض من الخط الحقيقي، فنتائج
الـ overflow محافظة (ممكن تفشل بدون ما تكون مشكلة حقيقية؛ إذا صارت قلي وبعدّل).

## 3. قرارات تصميم بتحتاج موافقتك

1. **لون "رشيد الطاقة":** `E85D04` ← `C2410C`. أغمق وأقل سطوعًا، بس هو شرط التباين لنص أبيض عليه.
   بديل: ترجع للون القديم وتخلّي النص عليه داكنًا (`black87`، تباينه 5.9:1) بدل الأبيض. قلي أي واحد بتفضّل.
2. **لون النص الثانوي:** `616161` بدل `black54` (أغمق شوي).
3. **الخط `Cairo`:** معرّف بالـ theme بس **مش مضمّن** بالتطبيق (ما في قسم `fonts:` بـ `pubspec.yaml`)، فالتطبيق بيستخدم خط النظام.
   إذا بدك Cairo فعليًا لازم تضيف ملفات الخط. (قرار تصميم عندك.)

## 4. قائمة فحص يدوي (على جهاز أندرويد فعلي)

- [ ] **TalkBack:** تنقّل بكل شاشة: كل زر ينقرا باسمه بالعربي (مش "زر" فقط أو إنجليزي). المبلغ يُقرأ "مصروف 12.5 دينار".
- [ ] **تكبير الخط:** إعدادات الهاتف ← حجم الخط الأكبر ← جرّب الشاشات: لا قص ولا تداخل (خصوصًا بطاقات الشخصيات، شاشة الـ Onboarding،
      مسار الهدف). بطاقة الشخصية فيها `SizedBox(height: 90)` للصورة، تأكد إن النص ما بيتقص.
- [ ] **حجم العرض:** نفس الاختبار بـ "حجم العرض" الأكبر.
- [ ] **RTL:** الأسهم والتنقل بالاتجاه الصحيح، أيقونة الإرسال متجهة لليسار، القوائم القابلة للسحب.
- [ ] **ألوان:** وضع "تصحيح الألوان" أو تدرّج الرمادي بالهاتف: كل حالة مالية (دخل/مصروف، مسار الهدف، الاقتراحات) لسا مفهومة.
- [ ] **حجم اللمس:** كل الأزرار قابلة للضغط بسهولة بإصبع (48dp تقريبًا).
- [ ] **تقليل الحركة:** مسار الهدف بدون أنيميشن عند تفعيل "إزالة الرسوم المتحركة".

## 5. فجوات معروفة (ما انعالجت)

- **حدود البطاقات غير المختارة** (`grey300`) تباينها منخفض؛ مقبول لأنها زخرفية والحالة ظاهرة بعلامة صح/نص.
- **الوضع الداكن:** غير موجود.
- **ترتيب التركيز (focus order)** بالقارئ الصوتي بالشاشات المعقدة (مسار الهدف): بدها اختبار يدوي.
- **صور الشخصيات** بدون نص بديل مقصود، لكن الشخصية بتنقرأ باسمها بالعنوان.
- **لقطات شاشة (golden tests)** غير موجودة.
